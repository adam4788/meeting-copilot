# Overlay lifecycle and publication contract

## Identity and retirement

- `snapshot_id` is an unguessable bridge-instance ID plus a monotonic presentation epoch. Native clicks must echo it alongside the row ID. The epoch advances on meeting/capture changes, corrected/removed question identities, authorization refresh, scope changes, and retirement. Missing/old identities are rejected; no row-only compatibility path exists.
- Swift captures the displayed identity in the button closure, not just the identity current when a delayed action runs. Before spawning a display, the bridge runs a bounded, stdin-free `--protocol-version` probe and requires `meeting-overlay/2`. Old helpers fail closed with an actionable rebuild error; no private snapshot is sent and no legacy click path is enabled.
- A mounted pane reads `/overlay/lifecycle` and claims its revision via `/overlay/claim`. Claims use compare-and-swap: a delayed older claim cannot replace a newer lifecycle. If the immediately preceding owner released after the ticket read, and no pane now owns the lifecycle, rejection includes a single `retry_revision`. The pane may retry that exact revision once; it never rereads a ticket to displace another claimant. Any intervening claim makes that retry stale. The backend issues an opaque `pane` capability; desktop capture Start, Show, Hide, and unmount Release carry that capability and a strictly increasing action counter. Desktop Start waits for ownership; unmount before the ticket resolves cannot launch capture. Backend Start shares the lifecycle lock and action fence with Release, so a start delivered after cleanup cannot resume capture. Release revokes the capability before pausing capture. Old panes cannot hide/show or pause the new owner, regardless of counter size. Non-release conflicts require reopen rather than silent reclaim. Legacy non-pane capture callers remain supported; the desktop always sends both fields.
- Explicit Show additionally mints a display `owner`. Scope requests must echo it and a display-local scope sequence. Hide, expiry, Clear, and New meeting revoke this display owner. Hide permits a later ordered Show from the same mounted pane; Release does not.
- An unchanged scope synchronization in an unchanged captured caller context is idempotent: it does not rotate authorization, cancel work, or erase completed output. The pane suppresses the redundant post-Show effect. Actual scope changes or changes to any captured context variable (except the internal action nonce) retire pending taps, admitted work, and completed output, then rebind authorization. This deliberately treats unknown host context changes conservatively.
- Every changed selection and every scope send invalidates the last acknowledged key. Manual and automatic sync share the same sequence/owner checks; a late broad response cannot acknowledge a subsequent narrow selection. Permission changes are sent immediately, without the former debounce. Failure of the current scope send triggers an ordered, capability-bound Hide. If even Hide cannot be confirmed (for example, total transport loss), the pane explicitly reports that closure is unconfirmed rather than claiming safety; the backend lease remains the offline fail-safe.
- An ordinary capture epoch transition in the same meeting preserves completed answers, including the interval between terminal publication and worker-map cleanup. Completion is explicit state, not inferred from an empty worker map. Pending/partial work is invalidated.
- A cancelled partial is marked incomplete with a partial-result warning before the next status pump. Capture-epoch retirement checks explicit completion even after the worker has removed its request mapping. Thus an unmapped partial cannot survive pause as a completed answer.
- Clear, explicit New meeting, and switching sessions synchronously retire and detach the overlay before changing meeting state, then tear down its helper before returning. This intentionally closes the overlay; reopen explicitly with Show. Already admitted provider calls use cooperative cancellation and cannot be retracted from an external service.
- Initial capture (no previous session) is not a meeting switch: an overlay explicitly shown before capture stays live. Successful Clear and actual meeting switches also reset local Hide/owner state immediately; reopening does not wait for the status reconciliation grace period.

## Lock order

- Lifecycle operations: `lifecycle_lock -> overlay_lock -> bridge.lock -> state.lock` when nested. Clear enters its retirement boundary before acquiring `state.lock`.
- Admission: `overlay_lock -> bridge.lock -> state.lock`. The backend slot's row mapping is published before leaving the admission guard, so Hide can cancel every admitted slot. The bridge calls the already-guarded transport entry point; it does not recursively acquire an injected plain `Lock`.
- Delivery: `stdin_lock -> bridge.lock -> state.lock` (the last only for cancellation on failure). Never acquire stdin_lock while holding bridge.lock. Headless append is inside the same validation/publication fence.
- A real helper's `push()` only queues a snapshot; it never performs pipe IO under overlay_lock. The writer pump uses a nonblocking OS descriptor and a 100ms frame deadline while holding bridge.lock. Thus invalidation waits for bounded publication, not an unbounded TextIO write/flush. A partial/failed frame retires the lifecycle and closes the helper rather than resuming a corrupt stream.
- Process teardown and joins are outside bridge/stdin locks; Clear teardown is also outside overlay/state locks. Production uses real pipe descriptors. Arbitrary blocking file-like test writers are not a supported helper transport.

## Injected transport contract

Injected `assist` methods must accept `expected_generation=`. BackendTransport additionally requires the capture epoch and current-question validation. There is no fallback to an old three-argument transport: retrying without admission preconditions would weaken the security boundary. Rejections release the reservation and show a bounded error type; TypeError includes the keyword contract. Assertion failures in admission/poll workers propagate instead of being mistaken for routine rejection/unavailability.

## Verification workflows

- `python -B -m unittest test_overlay_followup test_overlay_revision test_overlay_blockers test_overlay_privacy test_overlay_bridge test_server -v`
- `python -B verify_overlay_regressions.py`: temporarily mutates methods **in memory** to prove targeted tests fail, then restores production methods and reruns the blocker suite. It never writes source changes.
- `python -B verify_overlay_revision.py`: in-memory mutation checks for unchanged versus changed authorization, action fencing, synchronous meeting retirement, the completion/cleanup race, real OS pipe forwarding from `run()`, swallowed preflight timeout detection, and helper upgrade refusal.
- `python -B verify_overlay_followup.py`: Python memory-only and isolated JavaScript-copy mutations for capture admission/cleanup, release recovery without takeover, first capture, Clear, scope rollback/failure, partial cancellation, swallowed callback failures, and missing cancellation side effects. Scratch copies are created only inside `.test-tmp` and removed afterward; production files are never rewritten by mutation checks.
- `npm test`: full Python discovery, JavaScript syntax, desktop tests (including an effect-capable lifecycle harness with controlled timers).
- `swiftc -parse-as-library native/macos_overlay.swift -o .overlay-self-test && ./.overlay-self-test --self-test`
- `git diff --check`

Concurrency tests collect uncaught thread exceptions and join their workers. Test-injected callbacks additionally record exceptions before re-raising, because production error handling can legitimately catch callback failures. The scope-admission test releases admission before waiting for a scope writer: its old synchronous ordering progressed only on a swallowed gate timeout. The preflight regression proves Hide returns while preflight is still held, then explicitly releases and verifies successful callback exit. A barrier timeout is a failure, not evidence of a rejected stale request. The backend admission-lock regression tests backend admission directly: a bridge tap deliberately holds the outer overlay publication lock, so waiting for Clear inside that tap's state-lock gate would deadlock the test itself.

The deterministic suite includes buffered native events across identical questions, old pane owner requests, same-scope authorization refresh, full real OS pipes, in-flight delivery/Clear ordering, Hide at the admission exit before a queued provider executes, completed-answer preservation, non-dict stale poll results, plain publication locks, injected transport contract errors, and bounded-ID collision handling. A real FastAPI/BackendTransport integration test covers Show, unchanged synchronization during and after successful completion, stale pane cleanup, and required HTTP capability fields. `run()` is exercised through an actual OS pipe, and the compiled Swift binary is tested in headless self-test/protocol modes. Native GUI interaction, hardware capture, and live providers are not exercised by these offline checks.
